Three approaches to the data model

How sessions, batches, and ratings relate to each other

A

Session → Batches (recommended)

A Session is the top-level field event: you log weather once, then rate as many batches as you test that day. History tab shows sessions. Each session has a conditions block + a list of batch ratings.

Session #4 — 09 May 2026, mild, 18°C
  ├ Batch #3 (SLES, 4 days old) → rated
  └ Batch #5 (AOS, 1 day old) → rated
Clean for comparison. Conditions recorded once per outing.
B

Ratings directly on batches

No session concept. Each batch can have multiple rating entries (one per time you test it). Weather is logged per rating entry, not per session.

Batch #3 (SLES)
  ├ Rating on 09 May — mild, 18°C → rated
  └ Rating on 11 May — cold, 10°C → rated
Simpler. But if you test 3 batches on the same day you enter the weather 3 times.
C

Session → one batch only

Sessions exist but each session tests exactly one batch. Simpler session model, but you'd need to create a new session to switch batches mid-outing.

Session A — Batch #3, mild → rated
Session B — Batch #5, mild → rated
(same day, same weather, entered twice)
Least flexible. Not worth the extra friction.

I'd recommend A — click it and confirm in terminal, or pick B/C if that fits better.
